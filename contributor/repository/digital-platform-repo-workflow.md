# 数字化平台建仓与开源电子流指引

> 本指引收录 CANN 数字化协作平台（[HiCANN](https://digital.hicann.cn/)）「新建仓申请」与「开源申请」两条电子流的阶段定义与操作要点。
>
> 与[新建仓与仓开放操作指引](new-repo-operation-guide.md)的关系：**仓库新建与开源的流程阶段定义以本指引收录的数字化平台电子流为准**；《新建仓与仓开放操作指引》提供会议评审维度的补充（TSC / QA-SIG / PMC 议题申报、时间安排与最佳实践）。两者描述不一致时，以电子流为准。
>
> 来源：[cann/infrastructure 仓 docs/CANN-Digital-Platform](https://gitcode.com/cann/infrastructure/blob/master/docs/CANN-Digital-Platform/)（含各阶段操作截图）。

## 一、平台入口

- **登录方式**：GitCode 账号 OAuth 授权登录；管理类与审批类功能需具备对应岗位角色（联系平台管理员开通）。
- **发起申请**：
  - 新建仓：社区开发 → 仓库管理 → 全部仓库 → 「新建仓申请」
  - 开源：社区开发 → 仓库管理 → 所有仓库 → 「开源申请」（[直达链接](https://digital.hicann.cn/#/repo_manage/open_source_repo_application)）
- **查看进度**：仓库管理 → [申请与审批](https://digital.hicann.cn/#/repo_manage/application_approval)——我申请的 / 我审批的 / 与我相关的；支持按电子流单号搜索、按状态/类型筛选，勾选「待我处理」可只看当前轮到自己操作的。

## 二、新建仓电子流（共 8 阶段）

审批通过后系统自动完成建仓和仓库初始化配置。

| 阶段 | 名称 | 处理人 |
|---|---|---|
| 1 | 评审准备 | 申请人 |
| 2 | 材料预审 | 基础设施团队、PMC 成员、社区架构师 |
| 3 | 议题申报 & TSC 评审 | 申请人 |
| 4 | 新建仓库申请 | 申请人 |
| 5 | 基础设施团队审批 | 基础设施团队 |
| 6 | CI 与 SIG 配置 | 申请人 |
| 7 | CI 与 SIG 配置生效 | 申请人 |
| 8 | 绑定账号 | 申请人 |

### 第 1 阶段：评审准备（提交申请）

填写申请表单并提交，**提交即正式创建申请单**。主要填写项：

| 填写项 | 说明 |
|---|---|
| 是否同时新建 SIG | 勾选后需上传 SIG 申报材料 |
| 仓库名称 | — |
| 用途 | 自研软件（CANN）/ 自研软件（非 CANN）/ 生态项目 |
| 责任人 | 责任人 GitCode 账号 |
| SIG 组 | — |
| 仓库申报材料 | 上传[新建仓申报模板](../../templates/新建仓申报模板%20v0.2.pptx) PPT |
| SIG 申报材料 | 勾选新建 SIG 时必填（[SIG 组申报模板](../../templates/SIG组申报模板%20v0.2.pptx)） |

提交后支持更新材料。

### 第 2 阶段：材料预审

**基础设施团队、PMC 成员、社区架构师**三方全部同意后进入下一阶段；任一方驳回则申请停留本阶段，申请人可按意见重新提交材料（可反复直至通过）。

### 第 3 阶段：议题申报 & TSC 评审

按[新建仓与仓开放操作指引](new-repo-operation-guide.md)完成 TSC 议题申报与会议评审后，于该阶段填写评审时间并上传评审结论截图。

### 第 4 阶段：新建仓库申请

将建仓信息按模板提交 [infrastructure Issue](https://gitcode.com/cann/infrastructure/issues) 后，将 **Issue 链接**粘贴至页面解析；解析内容与第 1 阶段填写信息对比，确认无误后进入下一步。**最终建仓信息以该阶段展示信息为准**。

### 第 5 阶段：基础设施团队审批

基础设施团队审核 Issue 中的建仓信息，同意后新建仓成功。

### 第 6 阶段：CI 与 SIG 配置

录入 CI 配置 Issue 与 SIG 配置 PR（org-info.yaml / sig-info.yaml，见[新建仓与仓开放操作指引](new-repo-operation-guide.md)第 4~5 步），系统自动跟踪状态。

### 第 7 阶段：CI 与 SIG 配置生效

系统自动检查配置状态：**Issue 关闭、PR 合入**后，视为该仓库申请必要流程结束。

### 第 8 阶段：绑定账号（仅同时新建 SIG 时展示）

未勾选新建 SIG 时跳过：登录会议平台关联账号、订阅邮件列表。

## 三、开源电子流（共 7 阶段）

**仅仓库责任人**可以发起开源申请，经过 QA、PMC、基础设施团队审核后，将仓库转为公开仓。

| 阶段 | 名称 | 处理人 |
|---|---|---|
| 1 | 开源条件自查与测试报告 | 申请人 |
| 2 | QA-SIG 预审 | 社区质量审核员（QA） |
| 3 | QA-SIG 议题申报与评审 | 申请人 |
| 4 | PMC 预审 | PMC 成员 |
| 5 | PMC 议题申报与评审 | 申请人 |
| 6 | 基础设施审视 | 基础设施团队 |
| 7 | 正式开源 | 系统自动完成 |

### 第 1 阶段：开源条件自查与测试报告

填写自查表单并提交（提交后支持更新材料），进入 QA 预审。主要填写项：

| 填写项 | 说明 |
|---|---|
| TSC 评审时间 / 截图 | 平台表单必填项（见文末「待确认项」） |
| 测试报告 PR 链接 | 测试报告 PR 的链接 |
| 自查清单 | 按仓库类型对应完整集自查并勾选；须自查是否包含三方依赖、是否包含可执行逻辑，**不满足无法提交** |

自查依据：[仓库开源条件与目录结构指引](open-source-checklist.md)（文档 / 安全合规 / 工程规范 / CI / 测试报告 / 权限）。

### 第 2~3 阶段：QA-SIG 预审与议题评审

QA 预审自查材料；预审通过后于第 3 阶段填写 QA-SIG 评审时间并上传评审纪要截图（会议安排见[新建仓与仓开放操作指引](new-repo-operation-guide.md)）。

### 第 4~5 阶段：PMC 预审与议题评审

PMC 成员审核测试报告 PR 合入情况及 QA-SIG 评审纪要；通过后于第 5 阶段填写 PMC 评审时间并上传评审纪要截图。

### 第 6 阶段：基础设施审视

基础设施团队对仓库做最后审视，完成四项检查：**仓库检查、CI 检查、安全检查、权限检查**。

### 第 7 阶段：正式开源

审批通过后系统自动执行仓库开源。

## 四、撤回申请

两条电子流均支持：在「我申请的」列表中，进行中的申请可点「撤回」。撤回后申请单关闭、流程终止；如仍需建仓 / 开源，须重新发起申请。

## 五、与既有指引的差异处理（以电子流为准）

以下为收录的电子流与社区既有指引的差异，**均以数字化平台电子流为准**执行：

1. **开源的 TSC 评审**：平台开源自查表单要求填写「TSC 评审时间 / 上传评审截图」——开源流程**含 TSC 评审环节**，以电子流为准；《新建仓与仓开放操作指引》旧流程图（QA-SIG → PMC → 基础设施审视）不再作为阶段定义依据。
2. **建仓 Issue 通道的位置**：建仓 Issue 为电子流**第 4 / 6 阶段的组成部分**（Issue 链接由平台解析并自动跟踪状态），无需在电子流之外重复提交 Issue。
