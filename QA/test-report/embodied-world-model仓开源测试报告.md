# embodied-world-model 仓开源测试报告

## 1. 概述

本次验证 TD-MPC2、DINO-WM、DIAMOND 在昇腾 A2 上的 Torch NPU 与 OM 推理，共六条路径。覆盖输入生成、CPU FP32 基准、ONNX 导出、ATC 编译、设备推理、数值对齐和重复运行。

| 模型 | 本次验证范围 | 输出 |
| --- | --- | --- |
| TD-MPC2 | Acrobot 状态编码、5 步潜在状态及奖励分布预测 | latent `[1,5,512]`、reward logits `[1,5,101]` |
| DINO-WM | PushT 动作条件特征预测和图像解码，horizon=5 | `[1,9,3,224,224]`，含历史帧重建 |
| DIAMOND | Breakout 动作条件下一帧生成，3 步 Euler 扩散采样 | `[1,3,64,64]` |

输入由仓内脚本生成，每个模型使用一份固定输入。CPU、Torch NPU 和 OM 复用同一权重、输入与采样噪声。本次不覆盖训练、策略规划、真实轨迹任务成功率和真实机器人测试。

本轮发现并修复 DINO-WM Torch FP32 的逐元素精度问题，保留原验收阈值，未采用 CPU 模型推理替代 NPU 计算。

## 3. 测试结论

六条推理路径的功能、原定精度及短时重复运行检查均通过。最终版本采用 18 次独立进程运行，每次预热 3 轮、计时 20 轮，共 360 轮计时、54 轮预热；每个进程保存末次输出用于精度检查。六组后端的三份末次输出分别逐位一致，无 NaN/Inf，形状符合预期。

本报告定义的 24 项部署检查，最终回归 24 项通过，失败 0 项。首次对齐发现 1 项 DINO-WM Torch 精度问题，修复后回归通过；排障失败日志仍保留，不计入最终通过结果。

**发布结论：暂缓正式发布，建议先进入 QA 评审。** 真机部署部分已完成，代码修复已合入且社区门禁已通过，正式发布前仍需补齐现有 UT 执行记录及安全专项证据。不能以本报告的部署用例通过率替代仓库全部开源条件。

## 5. DFX 专项质量评估

### 5.1 安全

本次以普通 `developer` 用户运行，未新增服务或开放端口，未修改全局 Git 配置和平台文件权限。源码及权重做了版本、补丁和哈希核对。

本轮未执行完整漏洞扫描、Fuzz、病毒扫描或权限专项测试，也未取得这些专项的独立通过报告。现有社区工作流包含 CodeCheck，不能据此推断上述扫描均已通过。平台预装 `libop_plugin_atb.so` 的属主警告已保留，未擅自更改其权限，应由平台维护方确认。

### 5.2 可靠性

六条路径均完成 3 次独立进程运行，各后端保存的输出逐位一致。结束时 `npu-smi` 显示设备健康为 OK，无残留 NPU 推理进程。该检查不构成长时间无内存泄漏的证明。

### 5.3 性能

每后端有 60 个计时样本。均值为三次 `mean_ms` 的算术平均；范围为三次均值的最小值和最大值。P90 列给出各次 P90 的范围，不是合并 60 个原始样本后的 P90。

| 模型 | 后端 | 平均时延 / ms | 各次均值范围 / ms | 各次 P90 范围 / ms | Torch 峰值分配 / MiB |
| --- | --- | ---: | ---: | ---: | ---: |
| TD-MPC2 | Torch NPU | 7.108 | 6.969—7.189 | 6.896—7.274 | 5.79 |
| TD-MPC2 | OM | 0.501 | 0.499—0.503 | 0.510—0.520 | 未采集 |
| DINO-WM | Torch NPU，修复后 | 99.513 | 96.057—104.621 | 99.104—106.827 | 514.16 |
| DINO-WM | OM | 38.144 | 37.812—38.627 | 38.027—38.780 | 未采集 |
| DIAMOND | Torch NPU | 86.216 | 74.023—106.035 | 75.172—107.717 | 48.67 |
| DIAMOND | OM | 14.496 | 14.446—14.553 | 14.468—14.619 | 未采集 |

计时排除 Python 启动、权重加载、ONNX 导出、ATC 编译和模型初始化。Torch 计时包含模型计算、输出回传 CPU 及设备同步；OM 计时包含输入传入、ACL 执行和输出回传。DIAMOND 时延覆盖完整 3 步采样；TD-MPC2 覆盖 5 步 rollout。

DINO-WM Torch 的图像缩放在模型内计时，OM 的 CPU 图像缩放在计时前完成，因此不直接用表中两数计算纯算子加速比。Torch 峰值为框架分配器记录值，不是板卡总 HBM 占用。DIAMOND Torch 的跨进程时延有明显波动；本次未固定 CPU 亲和性或硬件频率，不能将单次最小值作为稳定服务承诺。

### 5.4 兼容性

本轮仅验证 Ascend 910B3、CANN 9.0.0、PyTorch 2.7.1 与 torch_npu 2.7.1.post4 的组合。未验证 A3、其他 CANN 版本、FP16/BF16、多卡、动态 batch 和动态输入形状。OM 应按实际 SoC 重新编译。
